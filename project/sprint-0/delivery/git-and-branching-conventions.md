# Convenciones de Git y Ramas

## Commits

- mensajes cortos
- verbo inicial claro
- scope cuando aporte contexto

Ejemplos:

- `feat(api): add auth controller`
- `chore(web): add playwright config`
- `test(api): cover sprint one flow`

## Regla operativa actual

- preferir commits pequenos
- idealmente 1 a 4 archivos por commit cuando el cambio lo permita

## Ramas

- `main`: base estable
- ramas de trabajo sugeridas:
  - `feat/...`
  - `fix/...`
  - `chore/...`
  - `docs/...`
